# Data coverage

本表描述当前适配器的实际能力。缺失字段不会按 0 次或已完成处理。任务卡片提示所需页面，悬停可查看来源、周期和读取时间。

| --- | --- | --- |

| 活跃与奖励 | `currency.900505`, `daily_task_reward` | 分开显示基础活跃和奖励领取；未核实的额外奖励不推断 |
| 金币／经验妖怪 | `lazy_cds.v`, `universal_lazy_cd` | 次数未下发则未确认；不把旧冷却缓存当成今天的 0 次 |
| 悬赏 | `MonsterHuntMgr._huntData._taskList` | 只有任务有效期包含当前时间才判定；普通任务的起止字段为 0 时批次仍未确认 |

| 逢魔首领 | 待核实 | 无可靠当日首领领奖字段时未确认 |

## Verification boundaries

自动测试使用合成回放覆盖计数、未下发、领奖、跨日／跨周失效、周一 06:00 边界、碰撞字典读取、账号隔离和权限所有权。

实时验证通过 MuMu CLI、ADB 文件／进程内存、Qt 控件状态和 Windows 窗口坐标进行。限时活动关闭期间无法核实其开放后的服务器对象；尚未核实的项目不会通过手动标记补齐。

新增字段时应同时记录客户端摘要、实际 getter、默认值、重置依据、领奖条件和脱敏回放。不要仅凭字段名称实现“已完成”。
