# Multi-instance window interaction

2026-10-14，yym 0.1.3 对拖动、重叠点击、焦点和最小化恢复进行了数据方式的回归验证。

## Fixes

* 设置原先通过 `QDialog.exec()` 打开，会阻止同一应用的其他侧栏接收输入。现在异步打开，仅阻止所属侧栏，并显式设置同一 GUI 线程内的 Qt transient parent。设置窗口的原生 owner 链可准确归属到对应侧栏。
* 模拟器最小化或隐藏时，同时隐藏所属设置窗口；恢复后保留尚未保存的选项。关闭侧栏或重新绑定实例时关闭所属设置窗口。
* Qt 在重新显示模态窗口时可能改变线程内的活动窗口和键盘焦点。恢复时保留原有线程输入状态，尊重期间发生的前台窗口变化，不主动激活其他应用。
* 原先将后台侧栏降为非置顶后，插入置顶模拟器之后又会使它变为置顶，导致每次跟随重复操作。现在匹配模拟器的层级；仅在所属层级或相邻位置变化时重新排序，保持窗口队列独立。

所有跨进程关系均为读取，侧栏不以模拟器为原生 owner。数据读取进程与任务判定逻辑没有改变。

## Verification

* 56 项自动测试通过，覆盖事件合并、实例隔离、层级稳定、模态范围、设置窗口隐藏恢复和焦点保护。
* `tools/verify_interaction.py` 使用另一个进程的两个临时模拟器窗口、两个真实侧栏及设置窗口，16 个交互场景全部通过。
* 完全重叠与部分重叠、两种刷新顺序、两个侧栏分别置前，共 8 次按钮按下／松开验证：前方按钮各收到 1 次，后方均为 0 次，期间原生 `WindowFromPoint` 命中保持稳定。
* 逐实例检查模拟器／侧栏／设置窗口焦点，另一个实例输入可用；分别最小化、恢复和隐藏／显示时，另一侧栏及其设置继续可见。未保存设置保留，恢复不改变原有焦点。
* 测试记录真实前台激活和受控前台标识两种模式。此次 10 次真实前台激活成功；其余 6 次因 Windows 限制，验证真实线程活动窗口与键盘焦点，并为层级判断注入前台标识。原生命中、可见性、窗口排序和按钮消息均由实际 Windows／Qt 处理。
* 置顶开关切换正确；稳定后 120 轮跟随没有冗余原生位置或层级写入。
* `tools/verify_follow.py` 在另一进程同时移动两个临时窗口：5 秒内各移动 623 次，1,173 条窗口通知合并为 218 次跟随，更新耗时第 95 百分位为 3.78 毫秒。侧栏 GUI 暂停 200 毫秒时，两个目标窗口仍各移动 17 次。
* `tools/verify_docking.py` 的双屏 100%／150% DPI 测试通过，包括左侧吸附、右侧回退、空间不足折叠和最小化恢复；原有 4 次重叠点击验证也再次通过。
* `tools/verify_live.py --interaction` 使用打包后的 0.1.3 程序，在两个真实 MuMu 实例上分别移动窗口、最小化和恢复。所属侧栏跟随正确，另一实例侧栏保持可用，最终还原窗口位置与原始最小化状态。35 秒内两个账号各产生 7 次快照，账号和窗口绑定正确，正常退出后两个 ADB 权限均恢复为原值。

这些是临时窗口上的可重复交互测试及运行中实例的只读窗口检查，不是对用户手工鼠标拖动体感的测量。未向游戏发送输入，未使用截图或 OCR。

模态范围参考 [Qt QDialog](https://doc.qt.io/qt-6/qdialog.html)，窗口排序参考 [Microsoft SetWindowPos](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowpos)。原始测试报告输出到忽略的 `build/interaction-validation.json`、`build/follow-validation.json` 和 `build/docking-validation.json`。
